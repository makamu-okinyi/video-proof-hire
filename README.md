# Donjo — Video Proof Hire

The Donjo main application (**hr.donjoafrica.com**): a video-first, proof-of-work hiring
platform. Applicants replace CVs with short video portfolios; employers, founders, and
admins review proof, run challenges, and manage hiring pipelines.

> Marketing site lives separately at **donjoafrica.com** (`donjoafrica.com` repo). This
> repo is the authenticated product app only.

## Tech stack

- **Vite** + **React 18** + **TypeScript**
- **Tailwind CSS** + **shadcn/ui** (Radix primitives)
- **React Router v6** (role-guarded routes), **TanStack Query**
- **Convex** — realtime database, Convex Auth (password + WebAuthn passkeys), file storage
- **vite-plugin-pwa** (installable PWA), **framer-motion**, **@react-pdf/renderer**

### Convex environment variables

Set with `npx convex env set NAME value` (add `--prod` for production).

| Variable | Purpose | Local default |
| --- | --- | --- |
| `JWT_PRIVATE_KEY`, `JWKS` | Convex Auth token signing (generated by `npx @convex-dev/auth`) | set once |
| `SITE_URL` | App origin used by Convex Auth | `http://localhost:8081` |
| `WEBAUTHN_RP_ID` | Passkey relying-party id: the bare domain, no scheme or port | `localhost` |
| `WEBAUTHN_RP_NAME` | Name shown in the passkey prompt | `Donjo` |
| `WEBAUTHN_ORIGINS` | Comma-separated allowed origins for passkey ceremonies | `http://localhost:8081` |

Production values:

```bash
npx convex env set --prod WEBAUTHN_RP_ID hr.donjoafrica.com
npx convex env set --prod WEBAUTHN_RP_NAME Donjo
npx convex env set --prod WEBAUTHN_ORIGINS https://hr.donjoafrica.com
npx convex env set --prod SITE_URL https://hr.donjoafrica.com
```

Passkeys are bound to the RP id: changing it later invalidates every registered passkey.

## Authentication

- **Email and password** (Convex Auth `Password` provider).
- **Passkeys (WebAuthn)**: sign in with a fingerprint, face or device PIN. Discoverable
  credentials give usernameless sign-in; typing an email first narrows the prompt to that
  account's passkeys (unknown emails get an indistinguishable decoy, so the response never
  reveals whether an account exists). The server verifies the challenge (single use, 5 minute
  expiry), origin, RP id, signature, signature counter and user verification before a session is
  issued. Users manage passkeys (add, rename, remove) under Profile > Edit profile and Employer
  settings > Account, and get a one-time dismissible "Add a passkey" nudge after login.
- **Google** sign-in is enabled via Convex Auth. Set `AUTH_GOOGLE_ID` and `AUTH_GOOGLE_SECRET` on the
  deployment (`npx convex env set`). The OAuth client must list the redirect URI
  `https://<deployment>.convex.site/api/auth/callback/google`. Apple sign-in is not offered.
- **Consent**: signup requires agreeing to the Terms of Use and Privacy Policy; the version and
  time are stored on the profile (`termsVersion`, `termsAcceptedAt`). Bump
  `CURRENT_TERMS_VERSION` in `convex/lib/legal.ts` and `LEGAL_VERSION` in `src/data/legal.ts`
  together to ask every user to re-consent. The legal text is a template with
  `TODO(owner)` placeholders and must be reviewed by a lawyer before launch.
- **Suspension**: suspended accounts are treated as signed out by every server function, their
  sessions are revoked, and the client signs them out and explains why.

## Admin console

The console lives at `/admin` (sober "Donjo Admin" sign-in at `/admin/login`: password and
passkey, no sign-up, no social buttons, generic errors). Unauthenticated visitors and
non-admins are redirected to the login page (non-admins are signed out with a generic "not
authorised" message); admin UI is never rendered before the server confirms the role. Admin
sessions sign out after 30 minutes of inactivity. `/admin` is `noindex` and `Disallow`ed in
`robots.txt`.

Sections: Overview, Analytics and traffic, Users, Venture review, Geography (Kenya county tile
map), Pipeline velocity, Jobs and challenges moderation, Plans and usage, System and security
(audit log, admin passkey coverage, data footprint, analytics retention). Every admin function
checks the role on the server (`requireAdmin`) and every mutation writes to `adminAuditLog`
(`logAdminAction(ctx, adminId, action, { detail })`). Reusable console building blocks are in
`src/components/admin/console/`.

### Creating the first admin

Admins cannot be created from the browser. Sign up normally at `/auth`, then from a machine
with Convex deploy access run:

```bash
npx convex run admin:grantAdminByEmail '{"email":"you@example.com"}'          # dev
npx convex run --prod admin:grantAdminByEmail '{"email":"you@example.com"}'   # production
npx convex run --prod admin:revokeAdminByEmail '{"email":"you@example.com"}'
```

Then sign in at `/admin/login` and add a passkey under Profile > Edit profile. Further admins
can be granted from Admin > Users > Grant admin.

### Analytics and privacy

First-party analytics only (no third-party trackers). The browser sends a random visitor id
(localStorage), a session id, path, referrer host, UTM tags, device class, browser/OS family,
timezone and language. **No IP addresses, cookies, fingerprints or user ids are stored**; Do Not
Track and Global Privacy Control are respected; bots and headless browsers and all `/admin`
pages are skipped. "Visitors by country" is an approximation from the browser timezone, not
geolocation. Events are deleted after the retention window (default 90 days, adjustable in
Admin > System). Signup-funnel stages after "opened sign in" are exact database counts.

### Plans

Employer plans (`plans` table) are defined in Admin > Plans and enforced server-side when
employers create jobs and challenges, reactivate them, or add shortlist entries (friendly
"upgrade your plan" messages). With no plan defined for an employer's tier nothing is limited.
These are in-app limits; the marketing pricing table on the public site is separate.

### Data rights

Settings pages offer **Download my data** (JSON) and **Delete my account** (`convex/account.ts`).
Erasure signs the user out everywhere, then deletes their profile, videos, applications,
shortlists, notifications, passkeys and auth records in batches; ventures left without founders
are removed. Retention exceptions: admin audit-log entries, messages the user wrote inside other
people's conversations (kept but blanked to "[message deleted]"), aggregate anonymous analytics,
and anything required by law. Admin accounts must have admin revoked first.

## Roles and route guards

Routes are guarded via `src/components/auth/`: `AdminRoute` (server-verified), `FounderRoute`,
`EmployerRoute` (nested `/employer/*`), `ReviewerRoute`.

## Forms and design system

Shared field primitives live in `src/components/ui/`: `Field` (visible label, hint, inline
error, required/optional, counter), `Input`, `PasswordInput`, `SearchInput`, `Textarea`, and the
accessible `Select` / `MultiSelect` combobox (keyboard, type-ahead, searchable above 8 options,
bottom sheet on phones). Styling comes from the `.field-control` class and scrollbar rules in
`src/index.css`. Every page sets a unique title with `useDocumentTitle`.

## Deploy checklist

1. `npx convex deploy` (production deployment; needs a deploy key).
2. Set production env vars:
   ```bash
   npx convex env set --prod JWT_PRIVATE_KEY "$(cat private.pem)"   # generate with npx @convex-dev/auth
   npx convex env set --prod JWKS '<jwks json>'
   npx convex env set --prod SITE_URL https://hr.donjoafrica.com
   npx convex env set --prod WEBAUTHN_RP_ID hr.donjoafrica.com
   npx convex env set --prod WEBAUTHN_RP_NAME Donjo
   npx convex env set --prod WEBAUTHN_ORIGINS https://hr.donjoafrica.com
   ```
3. Build the frontend with `VITE_CONVEX_URL` / `VITE_CONVEX_SITE_URL` pointing at production, and publish `dist/`.
4. Bootstrap the first admin (sign up at `/auth` first): `npx convex run --prod admin:grantAdminByEmail '{"email":"you@example.com"}'`, then sign in at `/admin/login` and add a passkey.
5. In Admin > Plans, define the `free` plan (and others) if you want employer limits enforced.
6. Have the legal text in `src/data/legal.ts` reviewed and fill the `TODO(owner)` placeholders.
